# CLICKI — сайт-визитка

Performance-платформа органических просмотров. Маркетинговый сайт с **двумя изолированными воронками** (бизнес и креаторы) и формами захвата лидов.

- **Frontend:** React 18 + Vite + React Router (SPA, SSR-ready через миграцию при необходимости)
- **Backend:** Node.js + Express (приём заявок, уведомления в Telegram/email, хранение лидов)

> 🔒 Ключевой принцип ТЗ: нигде на сайте, в коде, метаданных и медиа **нет денежных сумм, ставок, процентов и механики выплат**. Воронки разделены по URL и контенту.

## Запуск (разработка)

Нужен Node.js 18+ (проверено на 24).

```bash
# 1. Установить зависимости (client + server)
npm run install:all

# 2. Скопировать примеры конфигов и заполнить
cp server/.env.example server/.env
cp client/.env.example client/.env      # необязательно

# 3. В двух терминалах:
npm run dev:server      # http://localhost:4000
npm run dev:client      # http://localhost:5173
```

Vite проксирует `/api/*` на бэкенд (`vite.config.js`), поэтому фронт ходит на относительные пути.

## Сборка (production)

```bash
npm run build           # собирает client/dist
npm start               # запускает Express API
```

`client/dist` раздавайте любым статик-хостингом (Nginx, Vercel, Netlify). Так как это SPA с
client-side роутингом, настройте **fallback на `index.html`** для всех путей.

## Конфигурация бэкенда (`server/.env`)

| Переменная                        | Назначение                                              |
| --------------------------------- | ------------------------------------------------------- |
| `PORT`                            | Порт API (по умолчанию 4000)                            |
| `CORS_ORIGINS`                    | Разрешённые origin фронтенда через запятую              |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Мгновенные уведомления о заявках в Telegram     |
| `SMTP_*` / `MAIL_TO`              | Уведомления на email (опционально)                      |
| `RECAPTCHA_SECRET`                | Проверка reCAPTCHA v3 (опционально, защита от спама)    |
| `ADMIN_TOKEN`                     | Bearer-токен для просмотра лидов                        |

Конфигурация фронтенда (`client/.env`): `VITE_API_BASE`, `VITE_PHONE`, `VITE_TELEGRAM`,
`VITE_EMAIL`, `VITE_RECAPTCHA_SITE_KEY`.

## API

| Метод | Путь                  | Описание                                            |
| ----- | --------------------- | --------------------------------------------------- |
| POST  | `/api/lead/client`    | Заявка из клиентской формы (событие `client_lead`)  |
| POST  | `/api/lead/creator`   | Анкета креатора (событие `creator_lead`)            |
| GET   | `/api/admin/leads`    | Список собранных лидов (нужен `Authorization: Bearer <ADMIN_TOKEN>`) |
| GET   | `/api/health`         | Проверка живости                                    |

Лиды попадают сразу в несколько каналов: **Telegram**, **email** и локальный
append-only файл `server/data/leads.jsonl` (CRM-фоллбэк). Каждый канал изолирован —
сбой одного не блокирует остальные и не ломает отправку формы.

### Защита форм
- honeypot-поле + серверная валидация
- reCAPTCHA v3 (если задан секрет)
- rate-limit (10 заявок/мин с IP)
- обязательный чекбокс согласия на обработку ПД; для креаторов — подтверждение 18+

## 3D-слой

Сайт использует **Three.js + React Three Fiber** (`client/src/three/`):

- `Background3D` — глобальный анимированный фон (частицы + мягкие морфящиеся фигуры
  в фирменной палитре), фиксирован за всем контентом (`z-index: -1`). Секции сделаны
  полупрозрачными, поэтому 3D «дышит» под всем сайтом.
- `DeviceScene` — 3D-смартфон в hero-блоках (фиолетовый экран для бизнеса,
  зелёный — для креаторов; у креаторов его можно крутить мышью/пальцем).

**Производительность (важно для CWV — ТЗ 3.3):**
- Three.js полностью **code-split** и грузится отдельным чанком только **после
  первого рендера** — LCP-текст не блокируется (основной бандл ≈ 70 кБ gzip).
- При `prefers-reduced-motion` и на слабых устройствах 3D **не запускается** —
  показывается статичный CSS-фолбэк (градиент + силуэт телефона).
- На мобильных снижается число частиц и DPR (`useShouldRender3D`).
- 3D — чисто декоративный (`aria-hidden`, `pointer-events: none` у фона), кликам и
  доступности не мешает; никаких сумм/цифр на экранах устройств нет.
